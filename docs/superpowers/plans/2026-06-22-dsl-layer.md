# Tiny DSL Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tiny Robot-inspired authoring layer that compiles readable task files into existing deterministic YAML workflows.

**Architecture:** The DSL is compile-only for the first slice: `.rpa` input becomes schema v2 YAML, then the current `--validate-yaml`, `--preflight-yaml`, and `--run-yaml` paths own execution, evidence, and reports. Unknown keywords fail closed so AI-drafted workflows remain reviewable instead of becoming uncontrolled automation.

**Tech Stack:** Python stdlib parser, existing YAML workflow schema, existing CLI in `main.py`, pytest.

## DSL MVP Contract

Supported syntax:

```text
*** Settings ***
Name    Download Invoice
Tag     invoices

*** Variables ***
${portal_url}    https://vendor.example.com/login
${download_path}    downloads/latest-invoice.pdf

*** Tasks ***
Download Invoice
    Open Browser    ${portal_url}
    Verify Url Contains    /login
    Verify File Exists    ${download_path}
```

MVP keywords:

- `Open Browser <url>` → `browser.goto` with `url_contains` success check required separately.
- `Verify Url Contains <text>` → success-check-only step.
- `Verify File Exists <path>` → `file.exists` verification step.

Rejected in MVP:

- Arbitrary natural-language keywords.
- Secret interpolation beyond secret names.
- Direct execution from `.rpa`.
- Retry policy inference.
