# Domain documentation

This repository uses a single domain context.

Before changing domain behavior, read:

- `CONTEXT.md` at the repository root when it exists.
- Relevant decisions under `docs/adr/` when they exist.

Use glossary terms exactly in issue titles, specifications, code, and tests. If a proposed change conflicts with an accepted decision, surface the conflict explicitly instead of silently overriding it.

The domain-modeling workflow creates these files lazily when terms or irreversible decisions are resolved; their absence is not an error.
